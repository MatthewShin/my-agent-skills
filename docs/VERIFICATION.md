# 검증 지침

## 기본 원칙

- 정상 동작을 증명하기 전에는 작업을 완료로 기록하지 않는다.
- 변경 범위에 맞는 테스트와 정적 검사를 실행하고 실제 결과를 확인한다.
- 버그와 CI 실패는 로그와 실패한 테스트를 직접 확인해 원인을 해결한다.
- 필요하면 변경 전후 결과를 비교해 회귀가 없음을 확인한다.

## 관리 스크립트

`bin/skill-manager`를 변경했으면 다음 테스트를 실행한다.

```sh
sh tests/skill-manager-test.sh
```

설치 검증은 테스트가 만든 임시 `HOME`에서 수행한다. 실제 사용자 홈이나 기존 사용자 Skill을 수동 테스트 대상으로 사용하지 않는다.

## 문서 및 Skill

- 필수 루트 문서와 `docs/`, `tasks/` 문서가 존재하는지 확인한다.
- `CLAUDE.md`가 `@AGENTS.md`를 참조하는지 확인한다.
- 각 Skill의 디렉터리 이름과 frontmatter의 `name`이 같은지 확인한다.
- 문서와 Skill의 상대 경로 및 참조 대상이 존재하는지 확인한다.
- 커밋 전 `git diff --check`로 공백 오류를 확인한다.
