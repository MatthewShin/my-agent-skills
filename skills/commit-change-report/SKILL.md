# 커밋 변경사항 리포트

사용자가 지정한 Git revision을 실제 커밋으로 해석하고, 각 커밋의 부모 대비 변경을 근거로 `COMMIT-REPORT.html`을 만든다. 한 번의 실행에서 HTML은 한 장만 만들며, 여러 커밋은 문서 안에서 독립된 섹션으로 제공한다.

## 입력과 범위 확정

- 하나 이상의 SHA, tag 또는 branch를 받는다. `git rev-parse --verify <revision>^{commit}`으로 각각 검증하고, 해석된 commit hash가 같은 중복 입력은 첫 입력만 유지한다.
- 보고서 섹션은 사용자가 지정한 순서를 유지한다. revision이 branch 또는 tag라면 실행 시점에 해석한 commit hash를 보고서에 기록한다.
- 유효하지 않은 revision은 추측하거나 생략하지 말고 사용자에게 알려 보고서 생성을 중단한다.
- 일반 커밋은 해당 커밋의 부모와 비교한다. 부모가 없는 root commit은 빈 트리와 비교한다. merge commit은 첫 번째 부모와 비교하며, 이 기준을 각 섹션의 메타데이터와 제한사항에 명시한다.
- 이 Skill은 commit 단위의 diff만 다룬다. 작업 트리의 staged·unstaged 변경, `A..B` 범위, 테스트·빌드 실행 결과는 분석 대상에 섞지 않는다.

## 분석 원칙

커밋 메시지, 메타데이터, `git diff --stat`, 이름·상태 정보, 실제 diff를 함께 확인한다. 이름 변경과 복사는 Git의 탐지 결과를 사용한다.

- 변경 목적, 동작 변화, 데이터 흐름, 영향 범위, 위험과 검증 권고는 확인 가능한 근거만으로 작성한다. 의도나 실행 결과를 추측하지 않는다.
- 파일별로 추가·수정·삭제·이동·복사·이진 변경을 구분하고, 생성물·lockfile·기계적 포맷 변경은 핵심 로직과 분리한다.
- 전체 diff를 복제하지 않는다. 동작 이해에 필요한 핵심 hunk만 선택하고, 각 코드 조각에 파일 경로와 `무엇 / 왜 중요한가 / 전후 차이`를 붙인다. 의미 있는 hunk가 없으면 이유를 명시한다.
- Before / After, 직접 영향, 간접 영향, 영향 없음은 근거가 있을 때만 작성한다. 근거가 부족하면 `판단 근거 부족`으로 표시한다.
- 민감한 값(비밀키, 토큰, 비밀번호, 개인식별정보 또는 그에 준하는 값)이 보이면 원문을 HTML에 넣지 않는다. 해당 줄·hunk는 마스킹 또는 생략하고, 제한사항에 민감 정보 보호 처리를 기록한다.

## HTML 생성

[템플릿](assets/COMMIT-REPORT.template.html)을 사용해 프로젝트 루트에 `COMMIT-REPORT.html`을 생성한다.

- 보고서는 외부 CDN, 원격 폰트, 외부 스크립트 없이 바로 열리는 반응형 단일 HTML이어야 한다. 코드와 Git 메타데이터를 HTML escape하고, 색상만으로 상태나 변경 유형을 전달하지 않는다.
- 첫 화면에는 분석 시각, 대상 커밋 수, 전체 파일 수, 추가·삭제 줄 수, 전체 요약과 커밋 목차를 둔다. 목차는 각 커밋 섹션으로 이동해야 한다.
- 각 커밋 섹션에는 아래 정보를 순서대로 둔다.
  1. 해시, 제목, 본문, 작성자, 작성 시각, 부모와 비교 기준
  2. 목적·핵심 변경·파일 통계
  3. 파일별 변경 목록과 파일 역할
  4. Before / After 및 직접·간접·영향 없음 분석
  5. 핵심 diff hunk
  6. 회귀 위험, 권장 검증, 분석 제한사항
- 템플릿의 모든 `{{PLACEHOLDER}}`를 값 또는 HTML 조각으로 교체하고 남은 placeholder가 없는지 확인한다. 자동으로 브라우저를 열지 않는다.
- 기존 `COMMIT-REPORT.html`이 있으면, 문서의 대상 commit hash 목록이 이번 분석과 같을 때만 갱신한다. 다르거나 동일성을 판단할 수 없으면 덮어쓰지 말고 사용자에게 알린다.

## 완료 보고

완료 시 생성한 파일 경로, 분석한 commit hash 목록, 각 커밋의 핵심 변경 한 줄, 분석에서 제외하거나 마스킹한 내용과 실행하지 않은 검증을 짧게 알린다.
