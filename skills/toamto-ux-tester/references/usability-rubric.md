# UX/UI 사용성 평가 기준

## 점수 계산

각 기준을 0~10점으로 평가하고 동일 가중치로 합산한다.

- 0: 핵심 목적 달성이 불가능하거나 심각한 위험이 있음
- 2: 반복적으로 막히며 우회 방법도 불명확함
- 5: 목적은 달성할 수 있으나 뚜렷한 혼란·오류·불필요한 노력이 있음
- 8: 대부분 명확하고 효율적이며 일부 마찰만 남아 있음
- 10: 관련 flow에서 명확하고 일관되며 오류와 접근성까지 충분히 검증됨

중간 점수는 인접 anchor 사이의 증거에 따라 부여한다. 해당하지 않는 기준은 `N/A`로 제외하고 다음 식으로 100점 환산한다.

```text
총점 = 획득 점수 합계 / 적용 기준의 최대 점수 합계 × 100
```

각 점수에 증거 유형과 신뢰도 `High / Medium / Low`를 함께 기록한다. 실제 사용자 관찰 없이 10점을 부여하지 않는다.

## Severity

### Critical

- 핵심 작업을 완료할 수 없음
- 데이터 손실, 안전, 보안 또는 결제 위험이 있음
- 주요 기능이 특정 사용자나 입력 방식에서 완전히 접근 불가능함

### High

- 많은 사용자가 중단하거나 잘못된 결과를 만들 가능성이 큼
- 핵심 flow에 복구하기 어려운 오류나 큰 혼란이 있음
- 접근성 문제가 핵심 행동을 실질적으로 방해함

### Medium

- 작업은 완료할 수 있으나 반복적인 마찰, 탐색 비용, 수정 가능한 오류가 있음
- 보조 flow 또는 일부 viewport에서 사용성이 낮음

### Low

- 목적 달성에는 영향이 작지만 일관성, 이해도, 완성도를 낮춤
- 시각적 polish나 드문 edge case에 해당함

## 1. Clarity

확인 항목:

- 화면의 목적과 가장 중요한 행동을 빠르게 이해할 수 있는가?
- 레이블, 문구, 아이콘과 정보 위계가 모호하지 않은가?
- 다음 단계와 선택 결과를 예측할 수 있는가?

## 2. Navigation

확인 항목:

- 현재 위치와 이동 가능한 목적지를 알 수 있는가?
- 뒤로 가기, 취소, 종료와 재진입 경로가 자연스러운가?
- 핵심 목적까지의 경로가 불필요하게 깊거나 분산되지 않았는가?

## 3. Feedback

확인 항목:

- 클릭, 저장, 전송, 로딩과 완료 결과가 즉시 보이는가?
- 오래 걸리는 작업의 진행 상태와 중복 실행 방지가 있는가?
- 성공과 실패 메시지가 다음 행동을 설명하는가?

## 4. Error Prevention

확인 항목:

- 위험하거나 되돌리기 어려운 행동을 구분하고 확인하는가?
- 잘못된 선택을 하기 전에 조건과 결과를 알 수 있는가?
- 취소, undo, 수정 또는 안전한 복구 경로가 있는가?

## 5. Forms

확인 항목:

- label, 필수 여부, 입력 형식과 예시가 명확한가?
- validation 시점과 오류 위치·문구가 이해하기 쉬운가?
- 입력값을 불필요하게 지우거나 같은 내용을 반복 입력하게 하지 않는가?
- 키보드 종류, 자동완성, 탭 순서가 입력 목적에 맞는가?

## 6. Accessibility

확인 항목:

- keyboard만으로 순서 있게 조작할 수 있고 focus가 보이는가?
- label, heading, landmark와 semantic 구조가 올바른가?
- 텍스트와 UI 경계의 대비, 확대, screen reader 이름이 충분한가?
- 색상이나 모션 하나에만 의미를 의존하지 않는가?

## 7. Responsive UX

확인 항목:

- 작은 화면에서도 핵심 행동과 콘텐츠가 유지되는가?
- 가로 스크롤, 잘림, 겹침과 지나치게 작은 touch target이 없는가?
- 화면 크기에 따라 정보 우선순위와 조작 방식이 자연스럽게 바뀌는가?

## 8. Consistency

확인 항목:

- 같은 행동에 같은 컴포넌트, 용어, 위치와 상태 표현을 사용하는가?
- 플랫폼과 기존 디자인 시스템의 관례를 따르는가?
- 예외 패턴이 있다면 사용자 목적상 분명한 이유가 있는가?

## 9. User Effort

확인 항목:

- 불필요한 클릭, 입력, 기억, 대기와 화면 왕복이 없는가?
- 합리적인 기본값, 이전 입력 재사용, 일괄 처리 기회가 있는가?
- 단계를 줄이는 과정에서 오류 예방이나 통제권을 훼손하지 않는가?

## 10. States

확인 항목:

- loading, empty, error, success 상태가 모두 설계되어 있는가?
- disabled, selected, hover, focus, active 상태가 구분되는가?
- 각 상태가 원인, 현재 상황, 가능한 다음 행동을 설명하는가?

## 증거 기록 규칙

- 사용자 관찰: 참여자, 과업, 행동과 발화의 익명화된 요약
- 실행 화면: 재현 단계, viewport, 입력 방식, 실제 결과
- 코드: 관련 파일·컴포넌트와 확인한 조건
- 휴리스틱: 발생 가능성이 있는 문제와 추론 근거

서로 다른 증거를 섞어 하나의 사실처럼 표현하지 않는다. 재현하지 못한 문제와 수정 후 확인하지 못한 개선은 명확히 표시한다.
