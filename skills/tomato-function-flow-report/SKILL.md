# 함수 흐름 리포트

지정한 함수 또는 메서드의 정적 제어 흐름을 분석해 프로젝트 루트에 `FUNCTION-FLOW-REPORT.html`을 만든다. 리포트는 실제 코드에서 확인한 흐름과 근거를 설명하며, 런타임 동작을 추측하지 않는다.

## 대상 확정

- 사용자가 파일 경로와 심볼명을 함께 준 경우 해당 선언을 찾는다. 심볼명만 받은 경우에는 후보의 파일 경로와 선언 위치를 보여 주고 사용자가 하나를 고른 뒤 진행한다.
- 파일 경로·심볼명 조합으로 만든 canonical target id를 `파일경로::심볼명` 형식으로 정한다. 익명 함수나 overload는 선언 위치를 더해 구분한다.
- 대상 함수 본문, 필요한 타입·상수 정의, 직접 호출하는 프로젝트 내부 함수의 선언만 읽는다. 직접 호출 함수는 한 단계만 요약하며 그 호출이 다시 부르는 함수는 추적하지 않는다.
- 대상 파일 또는 심볼을 찾지 못하면 비슷한 이름을 추측해 분석하지 말고 중단한다.

## 분석 원칙

- 시작·종료, 의미 있는 처리 단계, 조건 분기, 반복, 조기 반환, 예외 처리, 상태 변경, 외부 I/O, 비동기 경계를 식별한다. 단순 대입이나 연속된 문장은 의미 있는 한 단계로 묶는다.
- 분기에는 실제 조건식과 각 경로의 결과를, 반복에는 진입 조건과 반복 본문의 효과를 기록한다. 정상·오류·조기 종료 경로는 구분한다.
- 직접 호출한 프로젝트 내부 함수는 이름, 정의 위치, 호출 목적, 확인 가능한 입력·반환 또는 부수 효과만 요약한다. 순환 호출은 재귀 확장하지 않고 순환 경계로 표시한다.
- 표준 라이브러리, 외부 패키지, DB·네트워크·파일 I/O, 동적 dispatch, reflection, 런타임 주입, 콜백 실행 순서를 확정할 수 없는 호출은 경계 노드로 표시한다. 확인할 수 없는 동작은 `정적 분석으로 확정 불가`라고 적는다.
- 각 노드와 경로 설명에는 파일 경로와 라인 범위를 붙인다. 필요한 최소 코드 조각만 인용하고, 비밀키·토큰·비밀번호·개인정보 등 민감한 값은 마스킹하거나 생략한다.

## 설계와 적합성 평가

- 먼저 함수의 책임, 입력·반환 또는 상태 계약, 주요 분기, 외부 의존성과 부수 효과를 `현재 함수 설계`로 요약한다.
- 다음 여섯 항목을 정적 코드 근거로만 평가한다: 책임 응집도, 제어 흐름 명료성, 입력·데이터 계약, 오류·복구 처리, 의존성·부수 효과, 변경·테스트 용이성.
- 각 항목은 `점수 / 5`, 코드 근거 위치, 판단 사유, 개선 의견을 함께 작성한다. 근거가 부족하거나 실행 환경이 필요한 경우에는 점수 대신 `판단 보류`와 이유를 표시한다.
- 점수는 5점(명확하고 적합함), 4점(경미한 개선 여지), 3점(개선 권장), 2점(유지보수 또는 회귀 위험), 1점(구조적 개선 우선)으로 일관되게 사용한다. 점수만으로 결론을 내리지 않는다.
- 전체 평가는 점수가 있는 항목만 한 자리 소수 평균으로 계산해 `평균 N / 5 · 평가 M개 · 판단 보류 K개`로 표시한다. 점수화한 항목이 없으면 평균을 만들지 않고 `평가 가능한 항목 없음`으로 표시한다.
- 점수 3점 이하 항목을 우선해 최대 세 개의 개선 의견을 `문제 → 근거 → 제안 → 기대 효과` 순서로 제시한다. 개선이 필요하지 않으면 그 사실과 근거를 적는다.
- 성능 수치, 실제 장애율, 배포 적합성, 외부 시스템의 내부 동작, 런타임 확인 없이 확정할 수 없는 보안 취약점은 점수화하지 않는다. 필요한 경우 분석 제한사항에 확인이 필요한 이유만 기록한다.

## HTML 리포트 생성

[템플릿](assets/FUNCTION-FLOW-REPORT.template.html)을 사용해 프로젝트 루트에 `FUNCTION-FLOW-REPORT.html`을 생성한다.

- 기존 파일이 있으면 HTML의 `report-target-id` meta 값이 이번 canonical target id와 같은 경우에만 갱신한다. 값이 다르거나 없으면 덮어쓰지 말고 사용자에게 알린다.
- 보고서는 외부 CDN, 원격 폰트, 원격 스크립트 없이 바로 열리는 반응형 단일 HTML이어야 한다. 템플릿의 `{{PLACEHOLDER}}`를 모두 치환하고, 코드·경로·사용자 입력은 HTML escape한다.
- 상단에는 대상 함수, 파일·라인, 분석 시각, 입력·반환, 주요 부수 효과, 전체 요약을 둔다.
- 핵심 흐름은 정적 inline SVG로 그린다. 노드에는 단계 번호와 텍스트 유형(처리·조건·반복·반환·오류·호출·경계)을 함께 표시하고, 화살표와 true/false 또는 오류 라벨로 경로를 구분한다. 색상만으로 의미를 전달하지 않는다.
- 다이어그램 선이 과도하게 교차하면 순차 단계를 묶고, 정상·오류·조기 종료 경로를 별도 경로 요약으로 보완한다. 코드에서 입증할 수 없는 호출 내부 흐름은 그리지 않는다.
- 대상 정보 다음에는 현재 함수 설계, 흐름도, 경로별 요약, 직접 내부 호출 요약, 적합성 평가, 개선 의견, 코드 근거, 분석 제한사항을 순서대로 둔다. 근거가 부족한 항목은 빈 내용으로 두지 말고 이유를 명시한다.
- 자동으로 브라우저를 열거나 코드를 실행·수정·테스트하지 않는다.

## 완료 보고

완료 시 생성 파일 경로, 대상 함수와 위치, 식별한 주요 경로 수, 한 단계로 요약한 직접 내부 호출, 정적으로 확정하지 못한 제한사항을 짧게 알린다.
